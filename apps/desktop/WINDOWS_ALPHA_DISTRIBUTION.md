# Windows x64 Desktop Preview distribution

**Status: functional Desktop Preview smoke passed; distribution pending.** The Windows shell, account flows, Windows Hello passkey, media, screen share and Tray passed physical testing. No signed NSIS installer or real A-to-B update has been validated. Do not send a download link to testers until the signed installer and update checklist below pass and the release is approved.

## Release operator checklist

The source of truth is `VERSION`, mirrored by the root and desktop manifests and `package-lock.json`. The current development version is `2.0.0-alpha.7`. The first signed Desktop Preview candidate is planned as A=`2.0.0-alpha.8`, with B=`2.0.0-alpha.9` reserved for the real update test. Create `.8` only after integrating 11.9 into `refactor/v2`; install and validate A before creating `.9`. This preview uses only `v<version>` annotated tags for a `2.0.0-alpha.N` version. Each release tag must point exactly to the then-current `refactor/v2` HEAD. Never create a release tag from the feature branch. Do not bump a version to repair packaging; change all mirrors together in an approved release change. The updater accepts only a greater `alpha.N` on the same `major.minor.patch` line.

Before any `publish=true` run, configure the GitHub environment **`desktop-alpha-release`** outside the repository with required reviewers, prevention of self-approval where supported, and deployment branch/tag restrictions appropriate to the workflow's `refactor/v2` dispatch. Store only these signing values as environment secrets:

- `WIN_CSC_LINK`: electron-builder supported Windows signing certificate reference or base64 PFX.
- `WIN_CSC_KEY_PASSWORD`: password for that certificate.
- `WIN_SIGNING_PUBLISHER`: expected certificate publisher name embedded into `app-update.yml`.
- `WIN_SIGNING_CERT_THUMBPRINT`: expected Authenticode signer thumbprint for the installer and application executable.

Never place the certificate, password, GitHub write token or generated package in Git. The release job gets a scoped GitHub Actions token with `contents: write` only after the environment gate. The validation job has `contents: read` and no signing secrets. Protect `refactor/v2` and release tags; review changes to the workflow and signing configuration before approving a run. Without environment protection, GitHub may create an unprotected environment automatically. No real Authenticode certificate is available in the current environment; certificate suitability and actual signing remain unverified. Do not set the signing secrets or run publish until protection and certificate suitability are verified.

The workflow is **manual only** (`workflow_dispatch`). Enter the existing annotated tag and leave `publish=false` for Windows validation without signing or release. After physical smoke and explicit approval, `publish=true` repeats checkout of the validated commit, builds on Windows x64, requires signing, checks the generated update metadata and Authenticode signatures, then creates a public GitHub prerelease. It refuses an existing release for that tag. It does not run on PRs or ordinary pushes. The local `package:win` script always passes `--publish never`.

The configured artifact set for one Windows x64 alpha version is:

| Asset | Purpose |
| --- | --- |
| `Cubic-Desktop-Setup-<version>-win-x64.exe` | Signed per-user NSIS installer |
| `Cubic-Desktop-Setup-<version>-win-x64.exe.blockmap` | Differential-update block map generated by electron-builder |
| `alpha.yml` | Electron-updater channel metadata with version, installer name and SHA-512 |
| `SHA256SUMS.txt` | Human/operator download verification |

The signed application's resources also contain `app-update.yml` with the fixed public `Gomaink/cubic` provider, alpha channel and signing publisher; that file is packaged, not uploaded as a separate release asset. The workflow validates the generated files together. Do not combine metadata and installers from different builds. GitHub's public HTTPS release feed supplies discovery; electron-updater checks the SHA-512 from channel metadata and the Windows signature/publisher before installation. SHA-512 detects mismatch against metadata; Authenticode binds the installer to the expected signer. Neither substitutes for review of the release source or protection of the GitHub account and tag.

NSIS is configured as a one-click, per-user install (`perMachine: false`) with no custom installer script, protocol handler, auto-start, PATH edit or silent background install. Standard shortcuts may be created by NSIS. UAC and SmartScreen behavior, including certificate reputation, must be observed on Windows. Do not advise testers to disable Windows security controls. Uninstall removes installed application files according to NSIS defaults; it does **not** promise erasure of the Chromium profile or its HttpOnly session cookie. Use Cubic logout when ending an account session; this workflow never reads or migrates cookies.

## Tester instructions — only after approved publication

Use Windows x64. Download the installer from the approved Cubic GitHub prerelease, confirm its expected publisher in Windows file properties, and install normally. The app opens the existing `https://cubic.goma.ink` service. The Tray offers **Check for Updates** and, only after a verified download, **Restart to Update**. Normal Quit does not install an update. The version is recorded in the release and executable properties; report the version, Windows version and steps to reproduce with a screenshot if useful. Never include passwords, cookies or private media in reports. Uninstall through Windows Installed Apps. If SmartScreen appears, report what it says; do not disable it.

## Physical Windows smoke and distribution acceptance

- **Passed on the functional Windows Desktop Preview:** shell launch and single-instance behavior; password login, logout, session persistence and internal/external navigation; Windows Hello passkey login; microphone, camera, output device and voice; explicit native screen picker with Window, Screen and second-screen sharing, cancellation, repeats and concurrent-request handling; Tray Open/restore and Quit. Electron 44 compatibility and normalized `securityOrigin` passed physical screen-share testing. Sharing remains video-only without system audio.
- **Notification limit:** the main process has a scoped notification permission policy, but the Web app does not yet emit native notifications; notification delivery was not part of the passed smoke.
- **Pending signed installer:** obtain a real Authenticode certificate, produce the signed per-user NSIS installer, verify its signature and the installed `Cubic.exe` signature and publisher, then test install, reopen, reinstall and uninstall, including UAC/SmartScreen behavior.
- **Pending protected release and A-to-B update:** verify the GitHub environment gate and publish A only after approval. With A installed, verify no update before B; then publish B and test detection, background download, responsive app, `update-downloaded`, explicit Restart to Update, version B and retained session.
- **Pending distribution negative cases:** offline/network failure, interrupted or corrupt package, invalid metadata, wrong signature/publisher, and equal/older/beta/stable candidate rejection. Verify failure leaves the installed app usable and does not expose an install action.

The signed installer, protected release, real updater and negative cases cannot be marked passed by static checks or by the functional smoke above. Alpha 11.9 distribution remains open until they pass.
